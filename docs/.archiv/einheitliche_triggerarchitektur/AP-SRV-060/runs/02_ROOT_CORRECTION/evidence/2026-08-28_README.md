## 6. F3: Kosten und Reichweite der Ladbarkeitsprobe

* Es werden ausschließlich die **ausgewählten** Klassifikatoren plus die zwei
  gemeinsamen Pipelinemodelle geprüft
  (`test_only_selected_artifacts_are_probed`).
* Das Ergebnis ist je Artefaktidentität (Pfad, Größe, mtime) memoisiert; eine
  fünfmalige Admission derselben Auswahl erzeugt genau **eine** Probe
  (`test_a_probe_result_is_memoised_per_artifact`).
* Ein Reload verwirft den Cache, weil Artefakte auf der Platte ersetzt worden
  sein können.
* Die Probe erzeugt keine dauerhafte Modellinstanz: die `InferenceSession` wird
  angelegt und sofort verworfen.
* Reihenfolge: erst Klassifikatoren, dann Pipeline – so gewinnt die
  spezifischste Ursache (`artifact_unloadable` statt `pipeline_unavailable`).
* Fehlt eine ONNX-Runtime vollständig, gibt es keine Probe statt einer
  pauschalen Ablehnung; auf einer solchen Maschine könnte ohnehin kein Wake
  Word laufen.

```text

  16 kHz, mono, 16-bit PCM WAV
  gesprochenes Wake Word aus dem Katalog (z. B. "Hey Jarvis")
  unmittelbar anschließender Nutzsprachanteil ohne Pause
  reales Mikrofon und reale Raumakustik
  bekannte akustische Wake-Endgrenze (Referenzannotation oder manuell markiert)

  Sample | Wake Word | Model | Scoreverlauf | Threshold
  Detection sample/time | akustische Wake-Endgrenze | Speech start
```
