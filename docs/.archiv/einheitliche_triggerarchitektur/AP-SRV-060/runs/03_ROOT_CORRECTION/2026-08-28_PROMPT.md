# 5. WAKE-HIT-MODELL

OpenWakeWord liefert fortlaufend Scores pro ausgewähltem Wake Word.

Die fachliche Erkennung arbeitet auf echten OpenWakeWord-Prediction-Frames,
nicht auf beliebigen Recorder-/Transportchunks.

Für jedes ausgewählte Wake Word wird unabhängig ein zusammenhängender
Trefferbereich verfolgt.

Konfigurierbare gemeinsame Kriterien:

```text
wakeWord.sensitivity
= Score-Schwelle

wakeWord.minConsecutivePredictionFrames
= Mindestanzahl aufeinanderfolgender Prediction-Frames
  mit Score >= wakeWord.sensitivity
```

Beispiel:

```text
Score-Schwelle = 0.70
Mindestanzahl = 10 Prediction-Frames
```

Eine Folge:

```text
0.73
0.78
0.81
0.85
0.88
0.90
0.91
0.89
0.86
0.83   <- Mindestanzahl erreicht
0.79
0.75
0.71
0.62   <- erster Frame wieder unter Schwelle
```

ist EIN zusammenhängender Wake-Hit.

Nicht 13 Trigger.
Nicht 13 Events.

## 5.1 Noch nicht qualifiziert

Solange die Mindestanzahl nicht erreicht ist:

```text
Score >= Schwelle
-> Trefferfolge wächst
```

Fällt der Score vorher wieder unter die Schwelle:

```text
Trefferfolge verwerfen
Zähler zurücksetzen
kein Wake-Hit
kein Event
```

## 5.2 Qualifikation

Sobald die Mindestanzahl erreicht ist:

```text
Kandidat = QUALIFIZIERT
```

Bedeutung:

```text
Der Kandidat hat jetzt alle Mindestbedingungen erfüllt.

Wenn kein anderer qualifizierter Wake-Hit vorher finalisiert,
ist dieser Kandidat weiterhin im Rennen.
```

Qualifikation ist noch NICHT die Finalisierung und noch NICHT automatisch das
Domain-Event.

## 5.3 Finalisierung

Ein qualifizierter Trefferbereich bleibt derselbe logische Wake-Hit, solange
sein Score weiter >= Schwelle bleibt.

Finalisierung:

```text
erster Prediction-Frame < Schwelle
nach bereits erreichter Qualifikation
```

Dann ist dieser Trefferbereich abgeschlossen.

# 6. MULTI-WAKE-WORD-ARBITRATION

Mehrere Wake Words dürfen gleichzeitig ausgewählt sein.

Primärregel:

```text
Der erste qualifizierte Wake-Hit, der finalisiert, gewinnt.
```

Beispiel `Alexa` / `Alexander`:

Wenn beide qualifiziert sind, aber der zusammenhängende Alexa-Trefferbereich
früher unter die Schwelle fällt:

```text
Alexa finalisiert zuerst
-> Alexa gewinnt
```

Das ist beabsichtigtes First-come-first-served-Verhalten.

Keine künstliche Nachwartezeit.
Kein "längeres Wort bevorzugen".
Kein nachträglicher Peak-Score-Wettbewerb.

## 6.1 Theoretischer Gleichstand

Wenn mehrere qualifizierte Kandidaten im selben Prediction-Frame finalisieren:

```text
1. früher erreichte Qualifikation gewinnt
2. wenn ebenfalls gleich: früherer Beginn der Trefferfolge gewinnt
3. wenn ebenfalls gleich: lexikographisch kleinste canonical Wake-Word-ID
```

Diese Tie-Breaker dienen ausschließlich deterministischer Auflösung
theoretischer Gleichstände.

Keine zusätzliche semantische Klassifikation.
Keine Nachwartezeit.
Kein komplexes Arbitration-Subsystem.

Sobald der Gewinner bestimmt ist:

```text
genau dieser Wake-Hit wird angeboten
andere gleichzeitig laufende Kandidaten dieser Entscheidung werden verworfen
```

# 7. OPERATIONALER AUDIO-NULLPUNKT / PRE-ROLL

Der operationale Nullpunkt ist definiert.

Er ist NICHT:

```text
erster Frame über Schwelle
Frame, an dem die Mindestanzahl erreicht wurde
Receptive-Field-Ende
extern annotierte "wahre" phonemische Wake-Endgrenze
```

Er ist:

```text
Trailing Edge des gewonnenen qualifizierten Wake-Hits
=
Übergang vom letzten Prediction-Frame >= Schwelle
zum ersten Prediction-Frame < Schwelle
```

Dieser Nullpunkt ist eine bewusste serverseitige Produktdefinition.

Er muss nicht erst durch externe Audioannotation erfunden werden.

Pre-Roll:

```text
wakeWord.preRollMs = 0
-> Audiofreigabe am operationalen Nullpunkt

wakeWord.preRollMs > 0
-> entsprechend viel gepuffertes Audio VOR dem Nullpunkt wieder mitnehmen
```

Konzeptionell:

```text
releaseBoundary = operationalZeroPoint - preRoll
```

mit sauberem Clamping auf tatsächlich vorhandene Audiohistorie.

Reale positive Wake→Speech-Aufnahmen bleiben wichtig für:

```text
empirische Default-/Range-Kalibrierung
Score-Schwelle
Mindestanzahl Prediction-Frames
Pre-Roll
Cooldown
False Positives / False Negatives
Usability
```

Sie sind NICHT erforderlich, um den operationalen Nullpunkt selbst zu definieren.
