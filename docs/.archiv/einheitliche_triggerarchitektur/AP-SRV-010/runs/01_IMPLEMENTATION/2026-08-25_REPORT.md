# Agentenbericht – AP-SRV-010 / Run 01_IMPLEMENTATION

**Status:** PASS

## Soll / Ist

AP-SRV-010 sollte den geerbten Controller auf genau einen kanonischen
Vordergrundslot umstellen. Implementiert sind die fünf Phasen `idle`,
`waiting_first_speech`, `segment_active`, `followup_wait` und
`closing_input`. Eine neue Admission erzeugt eine stabile `activationId`, eine
sessionsweit steigende `activationSequence`, genau eine gelatchte
First-Trigger-Quelle und einen defensiv kopierten, intern rekursiv
unveränderlichen Effective-Settings-Snapshot.

Ein weiteres `activate` in jeder nicht-idle Phase liefert deterministisch
`activation_locked`. Es ändert weder ID, Sequenz, Quelle, Settings noch
Controller-Version. Source-Merge und die Vordergrundphase `finalizing` wurden
entfernt. `generation` bleibt bis AP-SRV-040 als kompatible Gate-Bindung
erhalten und entspricht der `activationSequence`.

Der Sessionpfad schließt bei Finish, Cancel und Timeout zuerst das
generationengebundene Gate, stoppt danach gegebenenfalls die aktive Aufnahme
und vollendet erst dann `closing_input -> idle`. Ein später Recorder-Start-
Callback kann den geschlossenen Vordergrund nicht wiederbeleben und wird
unmittelbar gestoppt. Finalarbeit darf nach diesem Barrier im Hintergrund
laufen; eine neue Activation wird unabhängig davon zugelassen.

- AP-SRV-020 ergänzt Segment-Ledger, Pending-Registry, terminale Zustände,
  strikte `segmentSequence`-Publikation und definitive Korrelation älterer
  Background-Finals. AP-SRV-010 baut davon nichts vorweg.
- AP-SRV-030 ersetzt die geerbte additive Extension-Semantik durch Refresh-/
  Watchdog-/Recovery-Regeln. Scheitert ein technischer Gate-/Recorder-Close,
  bleibt der Controller heute sicher in `closing_input`; der 5-s-Recovery-
  Timer ist bewusst noch nicht implementiert.

  bestehenden v1-Nachrichten wurden nur additiv um `activationSequence`
  korreliert.
- Settings-Control-Plane, Wake-Katalog/Detection und Legacyabbau bleiben den
  späteren Paketen zugeordnet.
- Die 13 Skips der Vollsuite sind unveränderte optionale Engine-/Fixture-
  Abhängigkeiten; es gab keine Flakes oder Testfehler.
