## 1. Worum geht es?

Vier Kapazitäts-Entscheidungen + eine harte Grenze außen: **1 Prozess/viele Threads** (P6-01); **2 Lanes × 1 Job** (Rest wartet) (P6-02); **Queues mit eigenen Abwurfregeln** (alt-ersetzen/stale/verwerfen/trimmen) (P6-07..P6-12); **Modell/Zulassung als Grenze** (P6-18/P6-23/P6-24). **Kein RAM-/Disk-Guard, kein Druck-Unload** (statische Politik; harte Grenze = Container) (P6-21/P6-22/P6-30). **Keine Latenzzusage** – belegt: 1500ms Stale, 180s Lade-Timeout, 30s ForceFinalize, 3600s Idle, 0,02s Takt (4,1s abgeleitet markiert) (P6-09..P6-13/P6-15/P6-21).

Praxisbild: 8 Sessions + HTTP-Anfragen → Zulassung bis Grenze, aber Rechnen nur in 2 Lanes; Realtime coalesced/stale, Audio/Segmente getrimmt; „8 Sessions" ≠ „8× Durchsatz".

## 3. Threads (P6-01..P6-06)

Ein Prozess, eine App (kein workers/--workers; „workers" nur Scheduler-Dict); Skalierung = Threads, gemeinsamer Speicher/eine GIL-Domäne (horizontale Skalierung = außen) (P6-01). Lanes: je 1 Worker sequenziell (2 rechnend gesamt; shared → 1 Queue) – dritte Transkription wartet (kaputte ≠ wartende) (P6-02). Pro Session 3 Daemons (Text blockiert recorder.text; Recording; Realtime) – 8 Sessions ≈ 24 Threads + Grundlast (P6-03). Transient: Timer/Deadline (Token beendet Vorgänger) + Followup/Fenster – Bestand schwankt mit Fenstern (P6-04). Grundlast ~5-6 (Ready/Idle/3 Writer) + transient Kroko (LicenseCheck-background/Reconcile); leer ≠ 0 Threads (P6-05). HTTP: je Anfrage Executor-Thread (to_thread Decode/Inferenz, keine Pool-Config U1) – HTTP-Nebenläufigkeit außerhalb Session-/Speaker-Limits; Inferenz danach via Fair-Queue (P6-06/P6-25).

## 4. Queues/Latenz (P6-07..P6-16)

Final: Session-Deque 8 + Lane-global 64 (pro Lane; getrennt 2×64, shared 1×64); Ablehnung „voll" – Session schützt Vielschreiber, global schützt Lane (P6-07). Realtime: max 1 wartend (neu ersetzt alt, accepted+coalesced; final nie) – Verwerfen = normal, kein Fehler/Overload (P6-08). Stale: Deadline 1500ms ab Erzeugung; älter beim Dequeue → drop ohne Rechnen; final keine – fehlende Zwischenstände ≠ Session-/Final-Ausfall (P6-09). Audio: Queue unbegrenzt, Consumer trimmt >128 (älteste + Warnung); 128×512@16kHz ≈ 4,1s Rückstau (abgeleitet, nicht gemessen); Fenster = Consumer-Verarbeitung, Producer kann vorher wachsen (P6-10). Recorded: >8 → älteste discarded + Ledger + Warnung (droppedRecordedSegments/finalRejected) – fertig-aber-unverarbeitet geht verloren (P6-11). ForceFinalize ≥30s: Thread (flush/Speaker-aus/Warnung/forcedFinalizations) – Segmentgrenze, Session läuft (P6-12). Takt 0,02s (min 0,001s; Poll ~1ms): Latenz = Pause+Queue+Inferenz – Pause nur Taktgeber bei leerer Queue (P6-13). Tot: min/max_audio_seconds + vad_energy_threshold (validiert/persistiert, nie gelesen N2); degradation_threshold nur Reporting (N1) – Drehen ändert nichts (P6-14/P6-16/C4). Laden: Kalt/Idle wartet (180s+Warmup); Wechsel schließt Queues + ready-reset + wait_ready („lädt noch" ≠ „rechnet langsam") (P6-15).

## 5. Modell/Compute (P6-17..P6-20)

CPU-only (ValueError/device=cpu/choices); Whisper int8 → Modell (Kroko liest compute nicht U4); kein GPU-Pfad – keine pauschale int8-Aussage (P6-17). Ränge: Kroko 2; Turbo-Familie (--/-//--Endungen) 3 = Medium; sonst-large 4; medium 3; small 2; base/tiny 1; unbekannt Skip (keine Garantie). Ablehnung max>3 oder medium-Anzahl>Limit (2/1). Gleich Engine+Modell → shared; Policy-aus → Skip. Beispiele: medium+medium nur wenn 2 freigegeben; medium+large-v3 abgelehnt (Rang 4); large-v3-turbo+large-v3-turbo identisch → shared; small+base ok (P6-18). Kroko: 2 verschiedene → ValueError (Speicher/Native, nicht Komfort); gleich → shared (P6-19). Threads: OMP_NUM_THREADS = deployment.cpu_threads (Default 4) ohne Reader (Deklaration; Wirkung library U3); faster_whisper nur engine_options; Kroko 1; VAD 2+1; CT2 gesetzt; Ändern → messen, nicht ableiten (P6-20/C5).

## 6. Multiuser (P6-23..P6-26)

Sessions: Reservation sessions+reserved (parallele Zulassung ≤ max); drüber WS-error + limits + Close 1013 + Audit session_limit. Code-Default 4 vs config/VPS 8 – Effektivwert = geladene Konfiguration (C2) (P6-23). Speaker 4: nur neue verworfen (reject_current_recording/rejected+1/Warnung); Session bleibt; Freigabe Ende/Abbruch (weich ≠ Session-Limit) (P6-24). HTTP: openai-<reqId> Pseudo-Session (kein Session/Speaker-Slot; 64/Lane + 1-Inferenz/Lane); _pending unbegrenzt (N5); kein Vorrang (Round-Robin); 600s. max_sessions/Speaker schützen nicht vor HTTP-Ansturm – Absicherung vor Server nötig (P6-25). Overload: nur Ablehnung reason~„voll" → scheduler.overloaded (warning + queue.limit_reached); stale/coalesced/cancelled/Kroko/unbekannt/geschlossen still (fragil deutsch; kein Test Event-Pfad). „Kein Event" ≠ „keine Last" (P6-26).

## 7. Telemetrie/Retry/Health/Container (P6-27..P6-30)

Nur protokollierend (Hub geteilt; bounded 10000; voll → verworfen+gezählt N6): kein Steuerpfad; einziger Antwort-Einfluss /health via logging_ready. Log-Sink-Stau ≠ Inferenz-Stau (getrennt bewerten); Flush → 06.09 (P6-27). Kein Retry-Signal: Fehler/Reason (kein 429/503 N4); sofortiges Wiederholen → Retry-Sturm (nicht gebremst) (P6-28). /health O(Sessions): je Aufruf metrics + alle Snapshots (qsize/Stats), kein Cache, im Loop – Poll-Frequenz mit Session-Zahl denken (Felder → 06.10) (P6-29). Container hart: 6g/5cpu/512pids nur Orchestrierung; Python ohne MemoryError → OOM/Throttling (U5); Anwendung lehnt bei knapp nicht graceful ab; Health divergent (Root Liveness-only Test-erzwungen vs VPS ready and ok C1) (P6-30).

U1 Executor-Größe; U2 Footprint (nur Laufzeit-Messung); U3 OMP/CT2 library; U4 Kroko-int8; U5 OOM.
