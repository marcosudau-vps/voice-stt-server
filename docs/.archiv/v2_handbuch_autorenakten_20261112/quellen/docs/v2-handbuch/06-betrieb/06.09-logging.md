## 3. Kanäle/Schalter (G6-01..G6-06)

4 Kanäle, je enabled/stdout/path/max_bytes/backup_count/retention_days (G6-01). `enabled`/`stdout` = Sink-Schalter: Store nimmt weiter auf; enabled=false = kein Sink, Event kanonisch abrufbar (G6-02). Beispiel: system.enabled=false → keine System-JSONL, aber SQLite + /api/logs (Admin). Nur Store-aus = nichts kanonisch (Startentscheidung G6-21). Performance: `logging_enabled` Quelle (None, kein Store) vs `mirror_enabled` Sink (weiter SQLite, keine Datei); GET `performance.enabled`/`mirrorEnabled`, Hub-Sink `enabled` (C2-Verwechslung) (G6-03). Transkripte: performance immer drop; Audit nie; transcription final-nur-completed / full-alle-Transcription-Events (Audit/performance/system weiterhin ohne Transkripte) / none-keins; andere Kanäle drop; zentral/sink-unabhängig (G6-04). realtime: events (jedes Update) / summary (nur performance_summary) / off (keins); ungültig ValueError (G6-05). Defaults: INFO, request on/on/on →final, 10MiB/12/0, Europe/Berlin, events, Store an, Queue 10000 (min 100 startup-only), live an, Audio aus (G6-06).

## 4. Prozess-Log (G6-07..G6-09)

basicConfig (Format, ohne stream → stderr) → apply_level → uvicorn.run (level-lower); stdout = JSONL-Spiegel, stderr = Prozess-Log (Container-Trennung; json-file erfasst Strom) (G6-07). Level: nur bekannte Namen (sonst ValueError); Root/fastapi/uvicorn*/voicestt sofort; **nicht in /api/logging** (→ /api/config/CLI C5/N7) (G6-08). Recorder: ein stderr-Handler (Level recorder.level, markiert, idempotent); kein realtimesst-Datei-Handler (no_log_file True) (G6-09). Schema: basicConfig → apply → Recorder-stderr → uvicorn.run (kein Code, Ablauf).

## 5. Hub (G6-10..G6-15)

emit: sanitisieren → 6 Kontext heben → Payload (v1/ID/UTC-Z/Kanal/Event/Severity/Instanz/Kontext/data/meldung) → **Store-append** (aktiv) → Cursor → control-commit → Spiegel (Kanal-Schalter); ohne Store lokal; None = unbekannt/zu/Fehler (G6-10). Fehler: log + degraded(write) + None, **kein Spiegel** (JSONL kein Notfallarchiv); nur Append heilt (G6-11). Prio 0/2/1 (oben); nicht-blockierend FIFO/Prio; voll: schlechtester (höchste Zahl/jüngste Seq) nur bei besserem ersetzt, sonst neues verworfen; Größe startup-only (G6-12). Drops: nur Warnung, keine Route/Metrik (G6-13/N6). flush (Queues+Control wenn offen); close = flush→closed→Queues→Sentinel→joins-5s→Sinks→Store (geteilt No-Op) (G6-14). Control payload-frei: commit/store_error(kritisch, verdrängt)/store_recovered; Abonnenten lesen SQLite ab Cursor; Zustellfehler debug (G6-15).

## 6. JSONL (G6-16..G6-18)

`<root>/<YYYY-MM>/<YYYY-MM-DD>.jsonl`; Tag aus Event-Timestamp in Kalender-TZ (nicht Systemzeit); Rollover .1/.2 bei max_bytes (Weiterverwendung, Neustart-append); kompakt/UTF-8/flush; RLock (G6-16). Datei < max_bytes + existierende .1 = Rotation-vor-Neustart (kein Fehler). Retention: nur days>0, 1×/Tag/Sink beim Schreiben; Cutoff current-day − days; nur *.jsonl in YYYY-MM-Ordnern mit Präfix < cutoff, nicht offene; rmdir leer; Cutoff bleibt. Beispiel days=7 am 09.11. → bis 01.11. weg, 02.11. bleibt; days=0 nie (unbegrenzt) (G6-17). **backupCount nur gespeichert, nie gelesen: keine Wirkung** (Begrenzung maxBytes/retentionDays) (G6-18/C1/N4).

## 7. API/Zugriff (G6-19..G6-25)

GET /api/logging (Admin): dataRoot/enabled/stdout/file/transcripts/transcriptMode/saveAudio/audioDirectory/maxBytes/backupCount/retentionDays/performance{...}/transcription{...}/system{...}/TZ/realtimeDetail/liveEnabled/v2/sqlite_first/replayAvailable/eventStore{...} (G6-19). PUT: 5 Pfadfelder (audioDirectory/file/performanceFile/systemDirectory/transcriptionDirectory) → 400+fields (Pfade nur data_root); Mapping (enabled/transcriptMode/maxBytes/backupCount/retentionDays/performance*/transcription*/system*/TZ/realtimeDetail/liveEnabled); maxBytes>0/backupCount≥0/coerce; 400 wenn rejected sonst 200 + Neukonfig + Persistenz + config.updated. **level/Store/dataRoot still ignoriert** (N7) (G6-20). Namen asymmetrisch (C4): GET `performance.file` → PUT `performanceFile` (ebenso transcriptionDirectory/systemDirectory vs directory) – GET nicht unverändert zurückschicken. Start-only: store/queue_size (PATCH startup_only); live-ohne-store ValueError (Start) / invalid_dependency (Laufzeit) (G6-21/C6). Historie 3 Routen: Nicht-Admin nur 3 Kanäle + eigene Session (unzulässige Kanalwahl → leerer Platzhalter-Filter `__not_authorized__`, kein Fehlercode), system admin-only; Store-aus → 503 (auch Query-Exception); data/Cursor/scopes/deliveryMode; kein Datei-Fallback (G6-22). /ws/logs: live-aus 1008 log_live_disabled; Store-fehlt 1011; subscribe+accessToken+Scope; invalid_cursor/cursor_ahead 1008; hello(v2/sqlite_first/Cursor)/subscribed/gap(retention)/replay_completed/live replay:false. Offline-2-Tage + retention-1-Tag → gap, bei hello-Cursor neu (G6-23). v2-logAccess: available+Pfade/IDs/Cursor/v2/replay oder code/reason ohne Token; sonst Token+expires (G6-24). Literal v2 ohne Schema-Check (Client prüft selbst) (G6-25/N1).

## 8. Datenschutz (G6-26..G6-31)

Sanitizing rekursiv: Secrets (Namen+Suffix) / Audio / Query / bytes drop; Strings: Bearer-Token + Secret-Key-Value-Pattern (authorization/access_token/api_key/password/secret) bereinigt, kein generisches Label-Redacting; URL-Query bei Schema-Host/url-Keys drop; alle Kanäle/Store/Spiegel (G6-26). Modi: leer → request_log_transcripts (true final/false none); gesetzt maßgeblich; full/final/none; sync beidseitig; Block im Audit-Bereich wirkt global (C3); **keine Transkript-Beispiele** (nur Feldnamen) (G6-27). Kontext: 6 oben, Rest data; message → meldung deutsch (stabile Wire-Struktur) (G6-28). **Keine Anonymisierung/Pseudonymisierung** (nur Entfernen+Gating; IDs Klartext → personenbeziehbar schützen/aufbewahren/löschen; vor-emit/nachgelagert selbst) (G6-29/N2). Audio: nur saveAudio (Default aus) + HTTP-Upload; Tag + HHMMSS_micro_reqId.suffix (.audio); keine Retention (extern verwalten). 25 MiB (openai_max_file_bytes) ist das OpenAI-Upload-Limit, kein Archiv-Limit (G6-30/N5). Settings-Redaktion (public_dict/persistiert/Audit) ≠ Event-Schutz (Hub) – keine Verwechslung (G6-31).

## 9. Aufbewahrung (G6-32/G6-33)

SQLite opt-in/Kanal: 1. Append/UTC-Tag → DELETE<now-days + Watermark-UPSERT/Max je (channel,session) → retentionCursor → gap(retention). Ohne Schreiben kein Aufräumen (nur-lesend räumt nicht) (G6-32). **Kein VACUUM**: Datei bleibt groß (historisches Maximum planen) (G6-33/N3). Default 0 = unbegrenzt (JSONL + SQLite).

## 10. Ausfall (G6-34..G6-36)

disabled (kein Store) / ready / degraded (offener Lese- oder Schreibfehler; Heilung nur je Fähigkeit); Übergänge Typ/Zeit + store_error/recovered; status mit Cursorn (G6-34). `logging_ready = !live || available`; `ok = metrics.ok && logging_ready` (ready separat; eventStore mit; live-an + degraded → ready true/ok false; Tiefe → 05.09) (G6-35/U2). Vertrag: Historie 503 (auch Query-Exception), WS 1011, live-aus 1008; kein Datei-Fallback (G6-36).

## 11. Container (G6-37)

VPS: stdout json-file 20m×5 (rotierend/flüchtig); JSONL+DB persistent /data/logs (App; data_root aus config). Nachvollziehbarkeit = JSONL+SQLite (retention/maxBytes), nicht Container-Log. Andere Deployments ungeprüft (U1); 20m×5 VPS-Aussage.
