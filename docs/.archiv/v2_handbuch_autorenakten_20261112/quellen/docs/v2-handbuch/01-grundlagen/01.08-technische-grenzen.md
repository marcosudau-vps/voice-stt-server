# 01.08 Technische Grenzen

*Faktenbasis: `workflow/research/01.08.json` (G-01…G-22, N-G01…N-G10, U-01…U-06, C-G01…C-G05). Commit `a8993c5c`. Kein Diagramm (NOT_REQUESTED).*

Dieses Kapitel beschreibt, wo der Voice-STT-Server V2 endet: welche Engines, Plattformen, Modelle und Mandantenformen tatsächlich gebaut sind, welche Grenzen der Code aktiv durchsetzt und welche Fragen bewusst offenbleiben. Es ist eine **Grenzkarte für Planung**: Wer deployt, einen Client schreibt oder Kapazität schätzt, findet hier entschiedene Stellen – und Stellen, an denen niemand entschieden hat.

Drei Aussagearten werden strikt getrennt:

| Art | Bedeutung | Kennzeichnung |
|---|---|---|
| **Erzwungene Grenze** | Code prüft, lehnt ab oder bricht ab | Fakten-ID `G-…` |
| **ABSENCE** | Im Stand **nicht vorhanden / nicht gefunden** – kein Budget, kein Client. Codebefund, keine getestete Unmöglichkeit | `N-G…`, als ABSENCE benannt |
| **UNKNOWN** | Nicht gebaut, nicht gemessen oder nicht verboten – keine belastbare Aussage | `U-…` |

„Kein FD-Budget im Code" heißt nicht „unendlich viele Dateien". „Kein V2-Client im Paket" heißt nicht „V2 unbenutzbar". „Nicht für ARM gebaut" heißt nicht „läuft auf ARM nicht".

## 1. Worum geht es?

Vier Ebenen, leicht verwechselt:

- **Produktgrenze:** Teil des Artefakts vs. Entwurf im Repo (G-02, G-17, C-G04).
- **Plattformgrenze:** Wo gebaut/qualifiziert (G-06, G-07, U-03).
- **Laufzeitgrenze:** Paket-/Puffer-/Frist-/Slot-Durchsetzung (G-12, G-14, G-15).
- **Betriebsgrenze:** Was überlebt Neustart, was bei mehreren Instanzen (G-18, G-22, U-01).

Drei Konsequenzen: **CPU-only** ist erzwungen, nicht empfohlen (G-03–G-05). **Sitzungsverwaltung prozesslokal**: Neustart löscht Sitzungen, Replicas teilen nichts (G-18, U-01). **Keine Kapazitätszahlen**: Slots ja, Bytes/Threads/FDs/Durchsatz nein (G-12, G-14, U-02, U-04).

Belastbare Grenzen sind **strukturell** (was gebaut/abgelehnt wird). Dimensionierungszahlen fehlen nicht aus Geheimhaltung, sondern weil nicht erhoben.

## 3. Die belegten Grenzen im Einzelnen

### 3.1 Engines: zwei Namen, und was „vorhanden" bedeutet

Registry exakt zwei Einträge (`faster_whisper` Default, `kroko_onnx`); nur Normalisierung (strip/lower/`-`→`_`), **kein Alias-Mapping**; sonst `UnsupportedTranscriptionEngineError` (G-01). Boundary-Test weist 26 Namen ab – implementiert **und** getestet.

Fünf Altadapter nur `engineering/drafts` (ohne `__init__`, nicht importierbar, Manifest-prune); sieben entfernt; Wheel genau zwei Engine-Module (G-02). **„Im Repo" ≠ „im Produkt verfügbar"** (C-G04).

### 3.2 CPU-only: vier Prüfebenen und eine Bibliothek, die anders reagiert

Server erzwingt CPU vierfach (G-03): Factory (`device=cpu`, Index 0 vor Instanziierung); Laufzeit (`effective_device` wirft, Policy setzt); CLI (`choices=(cpu)`); Konfiguration (YAML/runtime ≠ cpu → `SystemExit`). Kroko: `provider != cpu` → `TranscriptionEngineError`, Rückgabe immer `cpu` (G-04). Installation: `cpu_only.py` (CPU-Index, `+cpu`-Pin, Checks gegen CUDA-/HIP-Variablen, GPU-Distributionen per Regex, Metadaten, CPU-Tensor-Op; `is_available` **kein** Beweis), verdrahtet in beiden CI-Umgebungen + Docker-Abbruch (G-05).

Bibliotheks-Unterschied (C-G02): Server **lehnt ab/bricht ab**, Bibliothek (`initialization.py`) **warnt + schreibt still um**. Getrennt betrachten.

### 3.3 Python-Version und Plattformen

| Variante | Python | Hintergrund |
|---|---|---|
| `voice-stt-server` (Extra `pro`) | `>=3.12,<3.13` | Kroko-Native nur cp312 |
| `voicestt` (ohne Variante) | `>=3.11` | ohne nativen Kroko-Pfad |

CI + Manifest erzwingen cp312; Image `python3.12` (G-06, G-22). Release nur `linux_x86_64`/`win_amd64`; Workflows nur Ubuntu 24.04/Windows; Kroko-Tags win*/linux*|manylinux*|musllinux*, amd64/x86_64, arm64/aarch64 (G-07). macOS/ARM/32-Bit: **nicht gebaut/qualifiziert, nicht formal verboten** – UNKNOWN, keine Laufzeitaussage (U-03).

### 3.4 Tuning: nur `custom`, Defaults keine Empfehlung

Register: exakt `custom` (Settings `{}`); sonst `ValueError` mit Verweis (G-08). Drei Presets an vier Eingängen abgewiesen (`--profile`, `--tuning-profile`, YAML, `runtime.json`; HTTP 400). Defaults Beam 5/3, Batch 16/16, Pause 0,02 s, Min-Länge 0,2 s, Post-Speech 0,55 s, Early 0,2 s (G-09); `custom` überschreibt nichts; `tuning_description` abgeleitet (nicht setzbar). Alter Profilname → Startfehler, kein stiller Fallback.

### 3.5 Wake-Word-Settings: bewusst unkalibriert

Fünf Schlüssel `calibration: pending` + Trace-IDs; Defaults neutrale Startwerte, kalibriert `EVIDENCE_BLOCKED` (G-10):

| Schlüssel | Stand |
|---|---|
| `minConsecutivePredictionFrames` | 1 |
| `cooldownMs` | 0 |
| `preRollMs` | 0 (keine Obergrenze; Historie clamp) |
| `detectorGain` | 1.0 |
| `vadThreshold` | 0.0 |

Startpunkte, keine Empfehlungen; `preRollMs` ohne geprüfte Obergrenze. Einordnung [02.04](../02-funktionsweise/02.04-wake-word.md), Schema [08.03](../08-referenzen/08.03-settings-katalog.md).

### 3.6 Runtime-Suppression ist schreibgeschützt

`runtimeSuppression.*`: `writable=False`; Patch → `read_only_runtime_authority`; nur `trigger_suppression.set`/Controller (G-11). Kein zweiter Schreibpfad (N-G08).

### 3.7 Nebenläufigkeit: Slots statt Budgets

Sessions + Sprecher, nicht Ressourcen (G-12): `max_sessions` (Default 4, config 8, C-G01), `max_active_speakers` 4. V1+V2 teilen Topf; voll → V2 `session.rejected`/`session_limit_reached` + 4409. Fünfter Client bei Default 4 → abgewiesen, keine Warteschlange; ausgeliefert 8 je Präzedenz. Alter V1-Client belegt Platz.

ABSENCE: kein Thread-/FD-/Connection-Budget (kein `RLIMIT`/Semaphore/`nofile`/`max_connections`; Manager ohne Zähler). Threads je Sitzung + Scheduler-Paar ohne Buchführung (G-12, N-G09). Kein unendlich – Host-Limit unbekannt (U-05).

### 3.8 Ein natives Kroko-Modell pro Prozess

Unterschiedliche Kroko-Modelle beider Lanes → Start-`ValueError`; gleiche → `use_main_model_for_realtime` erzwungen (eine Instanz). Kein zweites natives Modell (G-13, N-G07).

### 3.9 Modellgröße: Rangklassen statt Bytes

Ränge: kroko 2, `large-v3-turbo` 3, `large` 4, `medium` 3, `small` 2, `base`/`tiny` 1. Ablehnung bei max > 3 oder zu vielen mittleren Äquivalenten (2 bei `allow_two_medium`, sonst 1) (G-14). **Keine** Byte-/RAM-Obergrenze, keine Messung, kein OOM-Verhalten (U-02).

### 3.10 Laufzeit- und Transportlimits

Hart und sichtbar (G-15): Audiopaket 512 KiB → `AudioPacketError`; Metadaten 64 KiB; Kanäle ≤ 8; nur `pcm_s16le` frame-aligned; Final-Tiefe 8 / global 64 → Submit-Ablehnung; Realtime 1500 ms → stale; Audio-Queue 30 s; OpenAI-Upload 25 MiB; Handshake 10 s → 4408; `realtime_max` 20 s Feld. `limits_dict` (7 Einträge) via `/api/metrics` ([08.14](../08-referenzen/08.14-metrik-katalog.md)); Fristen [08.06](../08-referenzen/08.06-timing-katalog.md). 600-KiB-Frame → Paketfehler vor Verarbeitung.

### 3.11 V1 und V2 sind getrennte Transporte

| Merkmal | `/ws/transcribe` (V1) | `/ws/v2` |
|---|---|---|
| Admission | Query-Parameter | validiertes Client-`hello` |
| Hello-Richtung | Server-`hello` mit UUID | Client sendet `hello` |
| Manager | ConnectionManager | kein Manager; Legacy-Payload erreicht V2 nicht |
| IDs | hex-32 | kanonisch mit Bindestrichen; kompakt/groß abgelehnt, **kein Migrationspfad** |
| Hülle | `type: hello`, `start`/`stop`/… | `hello.accepted`/`incompatible`/`rejected`, `ack`, `snapshot`, `changed`; fünf Kommandos |

(G-16) Migration = Client neu bauen ([09.03](../09-anhaenge/09.03-v1-v2-unterschiede.md), [04.12](../04-schnittstellen/04.12-legacy-v1.md)).

### 3.12 Kein V2-Client im Paket

Pakete `VoiceSTT*`/`VoiceSTT_server*`/`api_fastapi_server*`/`voice_stt_server*`; UI (`static/index.html`, `package_data`) → `/ws/transcribe` (V1). V2-Client nur Testcode; `AudioToTextRecorderClient` = V1-Client (Recorder-Subprozess) (G-17, N-G05). V2-Spezifikation in [04.03](../04-schnittstellen/04.03-websocket-v2.md), kein fertiges SDK.

### 3.13 Sitzungen leben im Speicher

Dict/Reserve/Sprecher; Ende = weg. Persistiert nur Serverkonfiguration (atomar: Settings/Overlay/Revision); Session-Settings **nie**; `device`/`host`/`port`/Admin/OpenAI/Runtime-Pfade nicht (G-18, C-G05). „Prozess ohne Zustand über Neustart". Details [08.13](../08-referenzen/08.13-daten-persistenzschema.md), Verbindungen [02.01](../02-funktionsweise/02.01-session-management.md).

### 3.14 Replay-Cache ohne Obergrenze

Dict ohne Limit/Eviction; `setdefault` nie überschrieben; nur Teardown-`clear()`. Test: 1000 Einträge bleiben, Lookup funktioniert (G-19, N-G10). Linear mit `commandId`s je Sitzung – relevant für langlebige, kommandofrequente Sitzungen.

### 3.15 Streaming-Asymmetrie

`Base.supports_streaming=False`, `create_streaming_session` wirft – `faster_whisper` ohne Session. Kroko `True` + `StreamingSession` (G-20, N-G06). Betrifft Realtime-Lane, nicht Final. Pipeline [02.05](../02-funktionsweise/02.05-transcription.md).

### 3.16 Threads: indirekt, ungeprüft

`cpu_threads`/`num_workers` an `WhisperModel`; Kroko `num_threads` Default 1; Compose `OMP_NUM_THREADS` aus `VOICESTT_CPU_THREADS` (Default 4). Kein Serverfeld/Limit/Prüfung (G-21). Indirekte Stellschraube, kein Kapazitätsregler.

### 3.17 Ein Prozess, ein Port, ein Healthcheck

`python3.12 -m VoiceSTT_server.server --host 0.0.0.0 --port 8010 --device cpu --compute-type int8` (+ `local_files_only`). User 10001; Volume `/var/lib/voicestt`; EXPOSE 8010; Healthcheck nur `/health` (200 auch ohne Modell – sonst Restart-Loop). Kein Gunicorn/Worker/Broker/Replicas; Base-Digest gepinnt (G-22). „Healthy" ≠ „Modell bereit".

## 4. Was keine Grenze ist – und was offen bleibt

### 4.1 Nicht gebaut (ABSENCE)

Codebefunde, keine getesteten Unmöglichkeiten: keine dritte Engine (G-01/G-02); keine GPU (G-03–G-05); keine Presets außer `custom` (G-08); keine Session-Persistenz (G-18); kein V2-Client (G-17); kein Chunk-Streaming faster_whisper (G-20); keine zwei Kroko-Modelle (G-13); kein zweiter Suppression-Schreibpfad (G-11); kein Thread-/FD-/Connection-Budget (G-12); keine Replay-Begrenzung (G-19).

### 4.2 Offen (UNKNOWN)

| ID | Frage | Folge |
|---|---|---|
| U-01 | Cluster/Multi-Replica nicht verboten, Sessions/Replay prozesslokal | Faktische Grenze (ABSENCE): Instanzen teilen keinen Sitzungszustand |
| U-02 | RAM/VRAM unbekannt | Nur Rangklassen; keine Bytes/Messung/OOM |
| U-03 | macOS/ARM/32-Bit nicht verboten, nur nicht gebaut | Keine Laufzeitaussage |
| U-04 | Durchsatz/Latenz ohne Benchmarks | Keine Kapazitätszahl; Schwelle ≠ Nachweis |
| U-05 | FD-Limit nirgends gelesen/gesetzt | Host-Sache |
| U-06 | WS/Log-Volumen ohne Limit | Faktisch unbegrenzt, kein Vertrag |

U-01: mehrere Container möglich, aber keine gemeinsamen Sitzungen/Lastverteilung behauptet. U-04: Durchsatzzahlen wären erfunden.
