## 1. Worum geht es?

Zwei Fragen werden oft vermischt: (1) Kommt ein Client bis zum Server durch? (Transport: Adresse, Port, Listener.) (2) Darf er dann etwas tun? (Schranken: Admin-Key, Log-Token, OpenAI-Key.) Dieses Kapitel beantwortet nur die erste Frage. Die zweite steht in [05.01](05.01-sicherheitsarchitektur.md), 05.03, 05.05, 05.06 und 05.10.

**Erreichbarkeit ist im Code nur eine Bind-Entscheidung, kein Schutz.** Der Server öffnet einen einzigen Listener (W2-01, W2-04, W2-11). Alles danach sind Prüfungen in einzelnen Routen – nicht Port, Adresse oder Middleware (W2-05). **`0.0.0.0:8010` ist Erreichbarkeit, keine Sicherheit.**

| Begriff | Bedeutung |
|---|---|
| **Bind-Adresse** | Lokale Adresse, auf der der Prozess lauscht. `0.0.0.0` = alle lokalen IPv4-Adressen. |
| **Listener / Port** | Kombination Adresse+Port (Standard `8010`). |
| **TCP-Peer** | Gegenstelle einer Verbindung (`request.client.host`). |
| **Loopback** | Verbindung, die den Rechner nicht verlässt; Code erkennt genau vier Literale (Kap. 5). |
| **Middleware** | Schicht vor dem Handler – hier: keine (W2-05). |

## 3. Bind-Adresse, Port und Quellen

Default `host: "0.0.0.0"`, `port: 8010` aus `ServerSettings` (W2-01, server.py Z. 405–406). `0.0.0.0` ist Bind-, keine Zieladresse. CLI-Defaults identisch; YAML (`version: 1`) kann setzen, CLI gewinnt via `set_defaults`; Secrets/Unbekanntes → `SystemExit` (W2-02). Keine Bind-Env im Produktionspfad; `VOICESTT_PORT` nur Host-Port in Compose, intern fix 8010 (W2-03). Start: Defaults → YAML → CLI → Settings → `uvicorn.run` (W2-02). Praxis: Notebook ohne Argumente = `0.0.0.0:8010`; Browser via `127.0.0.1` = Loopback, Telefon via LAN = kein Loopback. Ob von außen offen, entscheiden Host/Firewall/Routing (W2-21, U2-03).

## 4. Transport, Middleware und Identität

uvicorn minimal: nur `host`/`port`/`log_level`/App (W2-04); kein TLS/Proxy-Header/workers/reload. Keine Middleware: `add_middleware` ohne Treffer (W2-05). Identität = `request.client.host` (W2-06, admin.py Z. 40, logs.py Z. 74); kein Forwarded. Beispiel: Browser lokal `127.0.0.1` → Durchlass; Laptop LAN `192.168.x.y` → 403 ohne Key; Proxy im Container-Netz → Bridge-Adresse → 403 (C2-1).

## 5. Loopback und Admin-Sichtbarkeit

Vier Literale: `127.0.0.1`, `::1`, `localhost`, `testclient` (W2-07, Testartefakt). Mit Key entscheidet nur der Key (401); ohne Key nur Loopback (sonst 403) (W2-08). **Proxy erzeugt nicht automatisch Loopback** (C2-1, U2-01): Server sieht Proxy-Adresse; Host-Netz → `127.0.0.1` (Loopback), Docker-Netz → Bridge (403), fremder Rechner → 403. `adminAuthRequired: false` in `GET /api/config` heißt „kein Key konfiguriert“, nicht „Admin frei“ (C2-4). `testclient` = In-Process-Aufruf, kein Netz-Bypass (C2-5).

## 6. Offene Fläche, ein Port

Offen ohne Key: `GET /`, `/health`, `/api/config` (+`adminAuthRequired`), `/api/metrics`, `/api/v2/info`, v2-Settings-Leserouten/Wake-Katalog (Schema/Server non-secrets, wake-words) – plus Swagger-Standardpfade (siehe U2-05). **Ein Listener für alles** (W2-11); keine Transport-Trennung Admin/Transkription (N2-04). Audio-WS ohne Transport-Auth (W2-12): Wer `8010` erreicht, kann Transkription öffnen. Portfreigabe = ganze Fläche; nur Gates schützen.

## 7. /health und startup_only

`/health` immer 200, `ready: false` gültig, kein Modellzwang (W2-10); Container-Health nutzt `127.0.0.1:8010/health`. `host`/`port` startup_only, kein Rebinding, nie persistiert, nicht in Registry (W2-13, N2-05). Änderung = Neustart.

## 8. UI same-origin (W2-14)

WS-URLs same-origin, nur `https` → `wss` (index.html Z. 1131–1138). Kein Backend-Host konfigurierbar (N2-08). Zugangsweg bestimmt WS-Adresse. TLS nur davor möglich.

## 9. Deployment-Befunde (nur Befunde, keine Zusagen)

Image: `EXPOSE 8010`, CMD `--host 0.0.0.0 --port 8010`, Health via Loopback (W2-15). Portable Compose: `${VOICESTT_PORT:-8010}:8010` ohne Host-IP, intern `0.0.0.0`, kein Proxy (W2-16). VPS-Compose: `127.0.0.1:2000:8010`, externes Netz, TLS-Vorbau außerhalb Repos (W2-17). Zwei Expositionen aus demselben Commit (C2-2). nginx historisch, per Test aus Compose ausgeschlossen, kein `X-Forwarded-For`, `/config` ohne Route (W2-18, C2-3). Tests nur Loopback/TestClient, `0.0.0.0` ungetestet (W2-19). Generator nur Host-Port (W2-20). Keine Firewall im Repo (W2-21, N2-06, U2-03).
