## 1. Worum geht es?

Optionale Fläche mit eigenem Schlüssel, ohne Konto/Rollen/Scopes: vorgelegter `Authorization`-Header exakt gleich konfiguriertem Wert oder Abweisung (P5-01/P5-05). Drei Zustände: offen (kein Key, kein 401/Audit), 401-Gate (Key konfiguriert, Header fehlt/falsch; POST + X-Request-ID), POST-404 (enabled=false nur POST, vor Auth, kein Audit, nur Transkriptions-Event) (P5-06..P5-12). GET prüft nur Key (200 auch bei enabled=false) (P5-13). Key schützt keine fremde Fläche; fremder Ausweis öffnet nicht /v1 (P5-16).

## 3. Quellen (P5-02..P5-04)

Settings `openai_api_key` vor ENV `VOICESTT_API_KEY` (pro Request gelesen); Settings gewinnt; ENV live nur wenn Settings falsy; CLI ohne ENV-Default (P5-02). Matrix: None/"" + leer → offen; ENV gesetzt → geschützt; Settings gesetzt (auch " ") → Settings (P5-02/P5-18). ENV-Name unspezifisch (VOICESTT_API_KEY). Kein YAML (SystemExit), keine Persistenz/Ladung, nicht in public_dict (nur enabled/Aliase/Bytes in YAML) (P5-03). Deployment via Compose/ENV/env_file; kein .env-Lader im Code (U5-01) (P5-04). Rotation = Quellenwechsel (+ ggf. Neustart); keine API-Rotation/Ablauf/Hash (P5-17).

## 4. Exakter Vergleich (P5-05)

`== "Bearer "+key`: ein Leerzeichen, case-sensitiv Wert, kein Trim/Folding, kein x-api-key/zweiter Header, kein compare_digest (Kontrast Admin, C5-01). Header-Name case-insensitiv (HTTP), Wert nicht. Tabelle: richtig → Handler; falsch/fehlend/abweichendes Muster → 401 (außer offen/deaktiviert).

## 5. Offen ohne Key (P5-06)

Gate None → Handler weiter; kein 401/Challenge/Audit. Default frischer Installation; Betriebsentscheidung, nicht Vergessen.

## 6. 401 + Audit (P5-07..P5-09)

401 + `WWW-Authenticate: Bearer`, Body invalid_request_error/null/invalid_api_key (Text nicht stabil); kein Echo; POST + X-Request-ID, GET ohne (P5-07). Genau ein Audit authentication.failed (Kanal audit, severity error, deutsch, path ohne Query, kein Key-Log); kein Erfolgs-Audit (P5-08). clientId normalisiert (strip, 1-128 [A-Za-z0-9._:-], Case bleibt, ungültig → client-<uuid>, fehlt → None); Test lowercased beweist nicht Produktion (C5-05) (P5-09).

## 7. POST-404 (P5-10/P5-11)

enabled=false → POST immer 404 vor Auth (auch mit Key): nur X-Request-ID, code null, kein Audit; nur Transkriptions-Event rejected/warning/api_disabled (P5-10/P5-11). Korrekter Key hilft nicht; 404 = Pfad-oder-deaktiviert (GET 200 unterscheidet) (P5-13). Code-belegt, ungetestet.

## 8. Zwei Routen (P5-12/P5-13)

POST-401: Audit + Hub-Event authentication_failed + X-Request-ID. GET-401: nur Audit, kein Event/Request-ID. GET: nur Key-Gate, 200 auch bei enabled=false. POST: enabled-vor-Auth. Modellliste ≠ Transkriptions-Verfügbarkeit.

## 9. Schalter (P5-14/P5-15)

Default true; nur --disable-openai-api / YAML; kein ENV; startup-only, nicht PATCH/v2-Registry (N5-07). Warnung (C): jeder erfolgreiche PATCH (auch fremder Werte) snapshotet den aktuellen enabled-Wert nach runtime.json; dieser überschreibt beim nächsten Start CLI/YAML (setzt data_root_path voraus); ungetestet (P5-15, U5-05, C5-06).
