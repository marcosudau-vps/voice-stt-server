## 4. Session-Patch (ST8-10..16)

**Hülle (ST8-10):** baseSettingsRevision int (kein bool) ≥0, changes nicht-leeres dict; sonst invalid_payload (Wire-Vorprüfung).

**Reihenfolge je Key (ST8-11):** unknown_key → wrong_scope (server) → read_only (writable false) → Koerzierung → Session-Validator nur selection.

**Atomar (ST8-12):** jeder Fehler verwirft alles; Fehler sortiert (field,code); nur nicht-schreibbar → invalid_payload; no_change ohne Bump; sonst +1 pro Transaktion (nicht pro Key), changed_keys sortiert.

**Konflikt (ST8-13):** stale base → settings_revision_conflict + stale_settings_revision, keine Mutation; in command.ack.

**Wirksamkeit (ST8-14/C-1):** live + next_activation sofort in effective (nicht unterscheidbar); next_session/server_restart nicht; freeze latched nur next_activation; Timing ms/1000=s.

**Filter (ST8-15):** Admission/Projektion nur scope==session; snapshot requested/effective/Revision aus EINER Projektion. Server-Keys nie im Session-Snapshot.

**Seed (ST8-16):** Server-Effektivwert + selection aus session_config; späterer Server-Patch schreibt bestehende Sessions nicht um.

**selection (ST8-23):** leer bei Wake konfiguriert → selection_required; Katalog fail-closed → unavailable.
