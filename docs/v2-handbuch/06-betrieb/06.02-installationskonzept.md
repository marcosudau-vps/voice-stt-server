## 1. Worum geht es?

Konzept vor Befehl: **ein Produkt** (`voice-stt-server`) mit **eingebetteter Native-Runtime** (Kroko, byte-genau im Wheel) und **CPU-only** als Kette; **zwei Wege** (pip/venv oder Container aus vorgebautem Wheel); Runtime entscheidet die **installierte Distribution**, nie der Schlüssel (K6-08). ENV `VOICESTT_CPU_ONLY=1` schaltet nichts (C6-07/B6-10). Keine Anleitung hier – Schritte in 06.03/06.04/06.05; Regeln in [05.11](../05-administration/05.11-sicherheitsrelevante-betriebsregeln.md).

Was dieses Kapitel nicht ist: keine Schritt-Anleitung, keine Kapazitätsplanung (N6-13), keine Bauanleitung, keine Freigabe unbelegter Plattformen.

## 3. Ein Produkt (K6-01..K6-05)

Ein Name hart geschlossen (`{"pro":"voice-stt-server"}`, sonst SystemExit; Duplikat + Guard-Test) (K6-01). Auflösung Env → geerbt (`_build_identity.json`) → Source-Checkout immer Legacy/`None` (K6-02). Legacy `voicestt` Default ohne Variante, kein Zweitprodukt (nur Metadaten/Python 3.11 vs 3.12) (K6-03). Pfad-Falle: `dist/voicestt/` (historisch) enthält `voice_stt_server-*.whl` (Name aus Distribution; Dockerfile kopiert Ordner) (K6-04). Ein Produkt pro Interpreter (mehrere → IdentityError; pip hindert nicht, Fehler erst beim Start); `voice-stt-server-pro` nur toleriert, nicht erzeugt (Zweck U6-02) (K6-05).

## 4. Native-Runtime (K6-06..K6-11)

Byte-genau gemerged ohne Kompilat, Kollisionen ausgeschlossen (Aufruf nach `resolve_kroko_wheel`) – kein Compiler/CMake auf Ziel (K6-06). Impure (`Root-Is-Purelib false`, genau ein Tag aus Kroko; linux_x86_64/win_amd64; Tag-Plausibilisierung) (K6-07). Distribution entscheidet (`runtimeSelectedBy installed-distribution`, `licenseKeyIsRuntimeCredentialOnly True`, Manifest `_embedded_kroko.json`; Dev nur Fallback) (K6-08). Kein Kroko-dist-info (kein Phantom-Paket), Lizenzen mit SHA-256 vs sources.json (K6-09). Python an Runtime (3.12 Public vs 3.11 Legacy, B6-01/02) (K6-10). Nur Linux/Windows qualifiziert (Windows Cross + Nativ-Nachquali; macOS nur Abwesenheit) (K6-11).

## 5. CPU-only (K6-12..K6-15, C6-07/C6-08)

Vier Ebenen: Vertrag (`cpu_only.py` + Fassade, CPU-Index/Constraint, Check; CI/Quali importieren; ps1/Dockerfile nicht) (K6-12); Image-Inline (CPU-Index + Constraint + `cuda is None/hip` + pip-grep; schwächer, Test nur Text) (K6-13); Native-CMake `GPU=OFF` (K6-22); Laufzeit Recorder-Warnung+cpu vs Server-Abbruch (CLI `choices cpu`, YAML SystemExit, Policy, Factory-Coercion) (K6-15). Semantik: Namen-Regex + markerbewusste Requires-Dist + Tensorprobe; `is_available()==False` kein Beweis (K6-14). ENV-Falle: `VOICESTT_CPU_ONLY=1` nirgends gelesen (nur Dockerfile/Compose), Deklaration kein Schalter – Verhalten prüfen (installiertes Torch, Start) (C6-07).

## 6. Wege (K6-16..K6-26)

Public vollständig (Sprachpfad sofort; Wake-Extra wegen tflite; Extras-Matrix) (K6-16). CLI kanonisch `voice-stt-server` + Aliase + Dev-Werkzeug (Guard-Test) (K6-17). Gleiche Importfläche (find_packages invariant; lazy ohne torch/PyAudio) (K6-18). Zwei Wege: pip/venv (ps1/requirements) vs Container (Dockerfile+Compose); kein Installer/Self-Update/Paket-Repo (K6-19). Image baut nichts (nur requirements + fertiges Wheel mit Extras; Tests verbieten editable/kroko-builder/COPY dist/kroko) (K6-20). Builder außerhalb (eigenes digest-Image, nur Orchestrator, nie Produkt-Dockerfile; Host git + Docker-Server) (K6-21). Kein config.yaml-Erbe (CMD/Env; `--config`→`VOICESTT_CONFIG`; Repo-config Betreiberpfade, Compose portabel+getestet) (K6-23). Kanäle PyPI + GHCR/Docker Hub; CI baut nur Dev (K6-24). sdist produktfrei (MANIFEST include/prune; include-existiert-Test; Backup-Filter) (K6-25). Guide nur Legacy (INSTALL_GUIDE nur variantenlos, nur voicestt; Public ohne Text) (K6-26/C6-09).
